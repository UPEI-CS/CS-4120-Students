Each score is precomputed from three common stratified CV folds on 900 development cases. The browser reveals the result, so this lab needs no Python installation. The search rules, in plain language

Start with four distinct random candidates. For each child, choose two parents using two-candidate tournaments. Prefer an eligible candidate over an ineligible one. Among eligible candidates prefer higher precision. If neither is eligible, prefer higher recall.

Take the first one or two configuration choices from parent A and the remaining choices from parent B. With probability 0.7, mutate one choice to another allowed value. Evaluate four children. Keep the best four distinct candidates from parents and children. This is a small teaching genetic algorithm, not TPOT.

Random search starts with the same four candidates, then samples four candidates with replacement per round. It also retains the best four distinct candidates seen. Both have a budget of 36 proposals, including the initial four. Revisited candidates reuse their saved score. Compare unique evaluations as well as proposals.

All scores are precomputed and fixed. Changing the search seed changes the search, not the dataset, CV folds or tree fitting seed. This tiny space could be evaluated exhaustively. The animation illustrates a mechanism, not evidence that evolutionary search is faster or better.

Where do these SHAP values come from?

We calculate exact Shapley values over all 32 subsets of the five inputs. For each subset, present features keep the customer's values. Absent features take values from 60 fixed development-background rows, and we average predicted probabilities. This defines an empirical interventional explanation game. It is not the tree-path contribution method in the earlier lab.

The baseline is this fitted model's mean predicted probability on those 60 background cases. For each feature, average its marginal contribution over all feature orderings. Baseline plus SHAP contributions equals the selected model's predicted probability.

With correlated inputs, hybrid cases can be unrealistic. The background and the rule for absent features affect the explanation. The term interventional here does not establish a real-world causal effect.

A research question: would another good model agree?

Now change the model while keeping the customer, background and explanation method fixed.

Recency and inactivity are duplicate measurements in this controlled example. Can the predictions agree while the feature attributions differ?

The empirical Rashomon set contains tested, eligible candidates whose precision is within the chosen tolerance of the best tested eligible precision. It is not a confidence interval or the set of all possible good models.

Stability asks what persists under a specified change. Consistent explanations can still describe a biased model or a misleading proxy.

Data, sources and reproducibility

Synthetic data only. 900 development cases for CV search, 300 audit cases for exploratory explanations, 300 reserved test cases unused here. All tree seeds are fixed at 7. Recency and inactivity are exact duplicates by design. Feature options always retain complaints, tenure and a noise input.
