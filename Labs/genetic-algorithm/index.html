See what a genetic algorithm selects

Each candidate is a decision-tree pipeline. Watch the algorithm change its feature choice, maximum depth and minimum leaf size.

Selection rule: recall must reach 70%. Among eligible candidates, prefer higher validation precision. Scores use the same three folds as the model-selection lab.

The current population: four candidate pipelines

These are configurations, not four already learned hypothesis functions. Each score summarises three separate fitted functions from cross-validation.

What do the choices mean?

All candidates use decision trees. The search chooses the activity inputs, maximum depth and minimum number of training examples in a leaf. Splits, thresholds and leaf predictions are learned during fitting.

Every candidate also includes complaints, tenure and an artificial random control. Recency represents time since last use; inactivity is an exact duplicate in this controlled synthetic dataset. Tenure means how long the person has been a customer. The values are standardised simulated inputs, not actual days, counts or months.

Four activity-input options × four depths × three leaf sizes = 48 possible configurations. This small space could be evaluated exhaustively. Evolutionary search is shown to explain the mechanism, not to claim it is the best algorithm for this problem.

Search history and evaluation rules

Two-candidate tournaments choose each parent. Eligibility comes first; eligible ties are ranked by precision. If both are ineligible, higher recall wins. Exact ties use candidate ID. Crossover takes the feature choice from parent A and the two tree settings from parent B. Mutation changes exactly one choice. Survival retains the best four distinct configurations from the population and child.

Scores were computed in advance. The browser reveals them at the evaluation step; it does not train Python models. Revisiting a configuration reuses its score. The search seed changes proposals only.
